📄 삼바웨이브 설치 가이드

Install Guide v2.0 2026-04-22

프로젝트 파일을 받은 후 로컬 개발 환경부터 프로덕션 레벨까지 단계별로 설정하는 완전 가이드입니다.

DB 마이그레이션 → 백엔드 서버 → 프론트엔드 → 확장앱

이 순서를 반드시 지킬 것. 역순으로 배포하면 없는 컬럼/API 참조로 서비스 장애가 발생합니다.

🐍 2. 백엔드 로컬 환경 설정

// 가상환경 생성 및 패키지 설치
cd backend

# 가상환경 생성
uv venv

# 가상환경 활성화
# Windows:
.venv\Scripts\activate
# Mac/Linux:
source .venv/bin/activate

# 패키지 설치
uv pip install -e .
uv pip install -e .[dev]

# .env 파일 생성
cp .env.example .env
주의: .env 파일은 절대 Git에 커밋하지 마세요. .gitignore에 포함되어 있지만, 반드시 확인하세요.

.env 필수 설정값

키설명필수
WRITE_DB_HOST Write DB 호스트 (예: localhost) ●
WRITE_DB_PORT Write DB 포트 (기본: 5433) ●
WRITE_DB_NAME Write DB 이름 ●
WRITE_DB_USER Write DB 사용자명 ●
WRITE_DB_PASSWORD Write DB 비밀번호 ●
READ_DB_HOST Read DB 호스트 (로컬에서는 write와 동일) ●
READ_DB_PORT Read DB 포트 ●
READ_DB_NAME Read DB 이름 ●
READ_DB_USER Read DB 사용자명 ●
READ_DB_PASSWORD Read DB 비밀번호 ●
JWT_SECRET_KEY JWT 서명 키 (임의의 긴 문자열) ●
environment 실행 환경: development 또는 production ●
DB_SSL_REQUIRED DB SSL 강제 여부 (false 로컬, true 프로덕션)
ANTHROPIC_API_KEY Anthropic Claude API 키 (AI 카테고리 매핑 등)
REDIS_URL Redis 연결 URL (Job 큐 캐시용, 없으면 인메모리 동작)
API_GATEWAY_KEY API 게이트웨이 키 (외부 앱 차단용)
PROXY_URLS 오토튠 프록시 URL 목록 (콤마 구분, 로테이션)
COLLECT_PROXY_URL 수집 전용 프록시 URL
Gemini / Cloudflare R2 설정: Gemini API 키, R2 버킷 정보는 서버 환경변수가 아닙니다. 최초 1회 설정 페이지(/samba/settings)에서 계정별로 입력하여 DB에 저장됩니다.
로컬 개발 팁: environment=development로 설정하면 디버그 로그가 활성화되고 DB SSL이 자동으로 꺼집니다. READ_DB_*는 로컬에서 WRITE_DB_*와 동일하게 설정해도 무방합니다.

🗃 3. DB 설정 옵션

로컬 개발 환경에서는 두 가지 방법 중 하나를 선택하세요.

🐊 옵션 A: 로컬 PostgreSQL 추천

Docker로 PostgreSQL을 로컬에 실행합니다. 프로덕션 데이터와 완전히 분리되어 안전합니다.

☁ 옵션 B: Cloud SQL 직접 연결 프로덕션

실제 프로덕션 DB에 연결합니다. 데이터 변경 위험이 있으니 주의하세요.

옵션 A: Docker로 로컬 PostgreSQL 실행

// Docker로 PostgreSQL 16 실행 (포트 5433)
docker run -d \
  --name samba-db \
  -e POSTGRES_USER=test_user \
  -e POSTGRES_PASSWORD=test_password \
  -e POSTGRES_DB=test_little_boy \
  -p 5433:5432 \
  postgres:16

위 명령 실행 후 .env 파일 설정:

WRITE_DB_HOST=localhost
WRITE_DB_PORT=5433
WRITE_DB_NAME=test_little_boy
WRITE_DB_USER=test_user
WRITE_DB_PASSWORD=test_password
READ_DB_HOST=localhost
READ_DB_PORT=5433
READ_DB_NAME=test_little_boy
READ_DB_USER=test_user
READ_DB_PASSWORD=test_password
DB_SSL_REQUIRED=false

옵션 B: Cloud SQL Proxy 사용 (프로덕션 연결)

// Cloud SQL Proxy 설치 및 실행 (Mac/Linux)
# Cloud SQL Proxy 다운로드
curl -o cloud-sql-proxy https://storage.googleapis.com/cloud-sql-connectors/cloud-sql-proxy/v2.9.0/cloud-sql-proxy.linux.amd64
chmod +x cloud-sql-proxy

# 프록시 실행 (GCP 프로젝트 ID, 리전, 인스턴스명으로 교체)
./cloud-sql-proxy --port 5432 <PROJECT_ID>:<REGION>:<INSTANCE_NAME>
주의: Cloud SQL에 직접 연결하는 경우, 실제 프로덕션 데이터가 존재합니다. 마이그레이션 테스트는 반드시 로컬 DB에서 먼저 검증하세요. 개발 환경(environment=development)에서 운영 DB 호스트 접속 시 서버가 자동으로 차단합니다.

🔄 4. DB 마이그레이션

// DB 스키마 생성 (최초 설치 시)
cd backend

# 모든 마이그레이션 적용
alembic upgrade head
성공 확인: INFO [alembic.runtime.migration] Running upgrade ... -> ... 메시지가 출력되면 정상입니다.

마이그레이션 관련 추가 명령어

// 마이그레이션 파일 생성 (모델 변경 후)
# 변경 감지 후 마이그레이션 파일 자동 생성
alembic revision --autogenerate -m "변경 내용 설명"

# ⚠️ 생성된 파일 반드시 검토: op.drop_table / op.drop_index 라인이 있으면 의도된 것인지 확인
# 의도 외 DROP이면 alembic/env.py의 모델 import 누락을 먼저 의심

# 생성된 파일 검토 후 적용
alembic upgrade head

# 이전 버전으로 롤백
alembic downgrade -1
마이그레이션 누락 검증: model.py 필드 추가/변경 시 cd backend && python scripts/check_migrations.py 실행으로 누락 여부를 사전 확인하세요.
DB 컬럼 추가 체크리스트: model.py 필드 추가 → alembic revision --autogenerate → 마이그레이션 파일 검토 → 로컬 alembic upgrade head 확인 → push (Cloud Build 빌드 후 수동 마이그레이션 적용)

🆕 5. 백엔드 서버 실행

// 개발 서버 실행 (권장)
cd backend
.venv\Scripts\python.exe run.py
// 또는 uvicorn 직접 실행
uvicorn backend.main:app --reload --port 28080
주의: uvicorn app.main:app 형태는 사용 금지입니다. 반드시 backend.main:app으로 실행하세요.

서버가 정상 실행되면 아래 URL에서 확인할 수 있습니다:

  • API 문서 (Swagger): http://localhost:28080/docs
  • ReDoc: http://localhost:28080/redoc

🐞 7. Chrome 확장앱 설치

삼바웨이브 확장앱은 소싱처 쿠키 수집, 상품 데이터 추출, 가격/재고 실시간 오토튠에 사용됩니다. 현재 버전: v2.10.27

  1. Chrome 웹 스토어에서 SAMBA-WAVE를 검색하거나 직접 링크로 접속
  2. Chrome에 추가 버튼 클릭 후 설치 완료
  3. 브라우저 우상단의 확장앱 아이콘 클릭
  4. 삼바웨이브 설정 페이지에서 발급받은 API 키를 입력 후 저장
  5. 무신사, KREAM 등 소싱처에 로그인하면 확장앱이 자동으로 쿠키를 서버로 전송합니다
API 키 발급: 설정 페이지(/samba/settings) → 계정관리 탭에서 API 키를 발급받을 수 있습니다. 키는 계정당 하나씩 발급되며, 재발급 시 기존 키는 즉시 만료됩니다.
extension vs extension-web: 저장소에는 두 가지 확장앱 빌드가 있습니다. extension/은 로컬 개발용, extension-web/은 웹스토어 배포용입니다. 코드 수정 시 반드시 두 디렉토리를 동일하게 유지해야 합니다.

🔐 8. 초기 설정 (최초 1회)

서비스를 처음 사용하기 전 설정 페이지(/samba/settings)에서 아래 항목을 순서대로 설정하세요.

  1. 관리자 계정 생성
    처음 가입한 계정이 자동으로 관리자 권한을 갖습니다. 이후 계정은 라이선스 발급 후 사용 가능합니다.
  2. 마켓 계정 연결
    스마트스토어, 쿠팡, 11번가, G마켓/옥션(ESMPlus), 롯데온 등 판매처 API Key를 설정 페이지 → 마켓 계정 탭에서 입력합니다.
  3. 소싱처 쿠키 수집
    Chrome 확장앱으로 무신사, KREAM, 롯데ON, ABC마트, SSG 등 소싱처에 로그인하면 쿠키가 자동으로 서버로 전송됩니다.
  4. Cloudflare R2 설정
    AI 배경제거 이미지가 저장될 R2 버킷 정보를 설정 페이지 → 외부 연동 탭에서 입력합니다 (Account ID, Access Key, Secret Key, Bucket Name).
  5. Gemini & Anthropic API 키 설정
    AI 이미지 처리에는 Gemini API 키를, AI 카테고리 매핑에는 Anthropic (Claude) API 키를 설정 페이지 → 외부 연동 탭에서 입력합니다. 서버 환경변수가 아닌 계정 DB 저장 방식입니다.
  6. 소싱처 계정 등록
    설정 페이지 → 소싱처 계정 탭에서 각 소싱처별 로그인 정보를 등록합니다. 자동 수집 시 사용됩니다.

▲ 9. 프로덕션 배포

상세 내용은 배포 가이드를 참조하세요. 핵심 단계만 요약합니다.

  1. GitHub Secrets 등록
    GCP_SA_KEY, DB 연결 정보, JWT_SECRET_KEY 등을 GitHub 저장소 Settings > Secrets에 등록합니다.
  2. Cloud SQL 인스턴스 생성
    GCP Console에서 PostgreSQL 16 Cloud SQL 인스턴스를 생성합니다. Read Replica 분리를 권장합니다.
  3. Cloud Run 서비스 생성
    백엔드 컨테이너를 Cloud Run에 배포합니다. 메모리 2Gi 이상 권장.
  4. Vercel 프론트엔드 연결
    GitHub 저장소를 Vercel에 연결하고 NEXT_PUBLIC_API_URL을 Cloud Run URL로 설정합니다. main 브랜치 push 시 Vercel이 자동 배포합니다.
  5. Cloud Build 자동 배포 확인
    main 브랜치에 push하면 Cloud Build가 자동으로 백엔드 이미지 빌드·Cloud Run 배포를 진행합니다. 완료까지 약 3~5분 소요.
  6. DB 마이그레이션 수동 적용
    Cloud Build는 DB를 자동으로 마이그레이션하지 않습니다. 모델 변경 시 Cloud SQL Proxy를 통해 직접 alembic upgrade head를 실행해야 합니다.
배포 순서 필수 준수: DB 마이그레이션 → 백엔드(Cloud Build) → 프론트엔드(Vercel) 순서를 반드시 지키세요. 역순 배포 시 서비스 장애가 발생합니다.

🔥 10. 문제 해결

✕ DB 연결 실패: connection refused
원인: PostgreSQL이 실행되지 않았거나 .env의 포트/호스트가 잘못됨
해결: docker ps로 컨테이너 상태 확인 → docker start samba-db 재실행. .env의 WRITE_DB_HOST/PORT 재확인 (로컬 기본 포트: 5433)
✕ [보안 차단] 개발 환경에서 운영 DB 접속 감지
원인: environment=development 상태에서 운영 DB 호스트가 .env에 설정됨
해결: 로컬 Docker DB를 사용하거나, 운영 DB 연결이 꼭 필요하면 environment=production으로 설정 (단, 데이터 수정 주의)
✕ alembic upgrade head 실패: relation does not exist
원인: 마이그레이션 파일 순서 충돌 또는 누락된 파일
해결: alembic history로 마이그레이션 히스토리 확인 → alembic stamp head로 상태 초기화 후 재시도. 또는 DB를 초기화 후 alembic upgrade head 재실행
✕ 확장앱 쿠키 전송 실패
원인: 백엔드 서버가 실행되지 않았거나 확장앱 URL 설정이 잘못됨
해결: 확장앱 팝업에서 백엔드 URL을 http://localhost:28080으로 재설정. chrome://extensions에서 확장앱 오류 로그 확인
✕ 마켓 API 인증 실패: 401 Unauthorized
원인: 마켓 API 키가 만료되었거나 설정이 잘못됨
해결: 설정 페이지에서 마켓 API Key를 재입력. 각 마켓 개발자 센터에서 키 유효성 확인. 쿠팡은 Vendor ID도 함께 확인 필요
✕ pnpm install 실패: engine incompatibility
원인: Node.js 버전이 요구사항(20+)보다 낮음
해결: node --version 확인 후 nvm 또는 공식 사이트에서 Node.js 20 LTS 설치
✕ uvicorn 실행 시 ModuleNotFoundError
원인: 가상환경이 활성화되지 않았거나 패키지가 설치되지 않음
해결: .venv\Scripts\activate (Windows) 또는 source .venv/bin/activate (Mac/Linux)로 가상환경 활성화 후 재시도
✕ ruff format 실패로 Cloud Build 빌드 실패
원인: Python 파일을 수정 후 ruff format 실행 없이 push함
해결: cd backend && .venv/Scripts/python.exe -m ruff format . 실행 후 다시 커밋·push. ruff check --fix .도 함께 실행할 것
✕ 마이그레이션 autogenerate 시 의도치 않은 DROP 발생
원인: alembic/env.py에 모델 import가 누락되어 전체 테이블 삭제 감지
해결: alembic/env.py에 새로 추가한 모델의 import 구문 추가 후 재생성. op.drop_table 라인이 있으면 반드시 육안 확인 후 삭제
더 많은 정보: 추가 문제는 개발 가이드 또는 팀 개발 가이드를 참조하세요.

💰 11. GCP 요금 절약 필수 설정

⚠️ 설치 직후 반드시 해야 하는 것 (안 하면 이미지 1TB 누적)

Artifact Registry Cleanup Policy 설정 (필수)

push할 때마다 Docker 이미지가 쌓여서 방치하면 한 달 만에 1TB, 월 ₩140,000 과금됩니다.

cat > cleanup-policy.json << 'EOF'
[
  {"name": "keep-latest-3", "action": {"type": "Keep"}, "mostRecentVersions": {"keepCount": 3}},
  {"name": "delete-old", "action": {"type": "Delete"}, "condition": {"tagState": "ANY"}}
]
EOF

gcloud artifacts repositories set-cleanup-policies cloud-run-source-deploy   --project=YOUR_PROJECT_ID   --location=asia-northeast3   --policy=cleanup-policy.json   --no-dry-run

✅ 이미 코드에 반영된 최적화 (클론하면 자동 적용)

  • --no-cpu-throttling 제거 → 유휴 시 CPU 과금 없음
  • VPC Connector 없음 → Cloud SQL은 Auth Proxy 소켓으로 직접 연결
  • CLIP 모델 미포함 Dockerfile → 빌드 시간 단축 + 이미지 크기 감소
