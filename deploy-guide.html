비용 목표

Cloud Run 월 ₩40만 → GCE VM 월 ₩10만 으로 약 75% 절감. e2-small + Cloud SQL Auth Proxy 사이드카로 VPC Connector 비용 제거.

배포 순서 원칙 [최우선]: 반드시 ① DB 마이그레이션 → ② 백엔드 → ③ 프론트엔드(Vercel) 순. 순서를 어기면 없는 컬럼/API 참조로 서비스 장애가 발생합니다.

배포 경로 3종 (백엔드)

현재 백엔드 배포는 다음 3가지 경로로 운영됩니다. GitHub Actions의 push 트리거는 비활성화되어 있고, workflow_dispatch 수동 트리거만 살아 있습니다.

(a) Cloud Build 자동 트리거 legacy

git push main → Cloud Build 트리거 → Artifact Registry → Cloud Run 새 revision

main 브랜치 push 시 Cloud Build가 자동으로 빌드 → Cloud Run에 새 revision을 띄웁니다. 현재 병행 운영 중이며 VM 전환 안정화 후 비활성화 예정입니다.

(b) GCE VM 배포 — deploy-vm.yml 수동 트리거 신규

workflow_dispatch → Docker 빌드/푸시 → SSH → VM → docker compose pull/up → 헬스체크

GitHub Actions Deploy to GCE VM 워크플로우를 수동으로 실행합니다. push 트리거 없음 — 모바일 등 PC 접속 불가 상황 또는 협업자 트리거용.

(c) 로컬 수동 배포 — scripts/deploy-cloudrun.sh

본인 로컬에서 직접 빌드 → Cloud Run 배포. 긴급 패치 또는 GitHub Actions 미가용 시 사용. VM 배포는 gcloud compute ssh samba-wave-vm로 접속해 sudo docker compose pull/up -d samba-api를 직접 실행해도 됩니다.

주의: git push origin main은 Vercel(프론트) + Cloud Build(백엔드 legacy)만 자동 트리거합니다. VM에는 자동 반영되지 않으니 deploy-vm.yml을 수동 실행하거나 SSH로 직접 pull 해야 합니다.

Cloud SQL 설정 (Cloud SQL Auth Proxy 사용)

중요: Cloud SQL은 퍼블릭 IP 직접 연결 금지. 반드시 Cloud SQL Auth Proxy를 통해 접근합니다. VM에서는 cloud-sql-proxy 컨테이너가 사이드카로 동작하며, 앱 컨테이너는 컨테이너명(cloud-sql-proxy)을 host로 지정합니다.

로컬에서 마이그레이션할 때 — Cloud SQL Auth Proxy

# Auth Proxy 다운로드 후 실행 (Windows) cloud-sql-proxy.exe fresh-sanctuary-489804-v4:asia-northeast3:samba-wave-db # 환경변수 (예시) set WRITE_DB_HOST=127.0.0.1 set WRITE_DB_PORT=5432 set WRITE_DB_NAME=railway set WRITE_DB_USER=postgres set WRITE_DB_PASSWORD=YOUR_PASSWORD cd backend && alembic upgrade head

GitHub Secrets 등록

리포지토리 → Settings → Secrets and variables → Actions에서 등록합니다. VM 워크플로우(deploy-vm.yml) 기준으로 갱신되었습니다.

Secret 이름용도설명
GCP_SA_KEY 필수 GCP 서비스 계정 JSON Artifact Registry 빌드/푸시, gcloud 인증
VM_SSH_PRIVATE_KEY 필수 SSH 개인키 Actions → VM SSH 접속용 (대응되는 공개키는 VM ~/.ssh/authorized_keys에 등록)
VM_HOST 필수 VM 도메인/IP api.samba-wave.co.kr 또는 외부 IP
VM_USER 필수 SSH 사용자명 일반적으로 ubuntu
KAKAO_API_KEY 카카오 알림 배포 성공/실패 카톡 전송 (선택)
KAKAO_REFRESH_TOKEN 카카오 알림 액세스 토큰 갱신 (선택)
Cloud Build (legacy) 경로는 별도 시크릿이 필요 없습니다. Cloud Build가 GCP 내부에서 직접 인증하기 때문. WRITE_DB_* 등 런타임 시크릿은 Secret Manager에 보관하고 Cloud Run 환경변수로 주입합니다.

GCE VM 배포 신규

스택 구성

Internet → Caddy (HTTPS, Let's Encrypt 자동) → samba-api (FastAPI:8080) → cloud-sql-proxy → Cloud SQL

도메인: api.samba-wave.co.kr · 인스턴스: samba-wave-vm (asia-northeast3-a, e2-small) · OS: Ubuntu 24.04 LTS · 디스크: 30GB pd-balanced

Phase 1 — VM 생성

gcloud compute instances create samba-wave-vm \ --project=fresh-sanctuary-489804-v4 \ --zone=asia-northeast3-a \ --machine-type=e2-small \ --image-family=ubuntu-2404-lts-amd64 \ --image-project=ubuntu-os-cloud \ --boot-disk-size=30GB --boot-disk-type=pd-balanced \ --tags=http-server,https-server \ --metadata-from-file=startup-script=deploy/vm/startup.sh \ --service-account=github-deploy@fresh-sanctuary-489804-v4.iam.gserviceaccount.com \ --scopes=cloud-platform # 방화벽 (포트 80/443) gcloud compute firewall-rules create allow-http-https \ --direction=INGRESS --action=ALLOW \ --rules=tcp:80,tcp:443 --source-ranges=0.0.0.0/0 \ --target-tags=http-server,https-server

startup.sh가 Docker, gcloud CLI, Artifact Registry 인증, samba-stack.service systemd 유닛을 자동 설정합니다.

Phase 2 — Cloud SQL 서비스 계정 키 + 파일 업로드

# Cloud SQL 접근용 서비스계정 + 키 gcloud iam service-accounts create samba-vm-sql \ --project=fresh-sanctuary-489804-v4 gcloud projects add-iam-policy-binding fresh-sanctuary-489804-v4 \ --member=serviceAccount:samba-vm-sql@fresh-sanctuary-489804-v4.iam.gserviceaccount.com \ --role=roles/cloudsql.client gcloud iam service-accounts keys create sa-key.json \ --iam-account=samba-vm-sql@fresh-sanctuary-489804-v4.iam.gserviceaccount.com # VM에 docker-compose / Caddyfile / sa-key.json 업로드 gcloud compute scp deploy/vm/docker-compose.yml deploy/vm/Caddyfile sa-key.json \ samba-wave-vm:/tmp --zone=asia-northeast3-a gcloud compute ssh samba-wave-vm --zone=asia-northeast3-a \ --command='sudo mv /tmp/{docker-compose.yml,Caddyfile,sa-key.json} /opt/samba/'

Phase 3 — /opt/samba/.env 배치

# 실행 환경 ENVIRONMENT=production DB_SSL_REQUIRED=false # Cloud SQL Proxy 쓰면 false COMMIT_SHA= # CI가 자동 세팅 WEB_CONCURRENCY=1 GUNICORN_CMD_ARGS="--timeout 300 --graceful-timeout 300" TERMINATION_GRACE_HACK=1 # DB (Cloud SQL Auth Proxy 컨테이너 host로 접속) WRITE_DB_HOST=cloud-sql-proxy WRITE_DB_PORT=5432 WRITE_DB_NAME=railway WRITE_DB_USER=postgres WRITE_DB_PASSWORD=<시크릿> READ_DB_HOST=cloud-sql-proxy READ_DB_PORT=5432 READ_DB_NAME=railway READ_DB_USER=postgres READ_DB_PASSWORD=<시크릿> # 인증/시크릿 JWT_SECRET_KEY=<시크릿> API_GATEWAY_KEY=<시크릿> # ESMPlus / 카카오 알림 등 도메인 시크릿 ESMPLUS_HOSTING_ID=hlccorp ESMPLUS_SECRET_KEY=<시크릿> KAKAO_API_KEY=<시크릿> KAKAO_REFRESH_TOKEN=<시크릿> LOTTEON_FULL_PAGING_ENABLED=1
주의: PROXY_URLS / COLLECT_PROXY_URL은 불필요. DB proxy_config 단일 소스로 전환 완료(2026-04-24). Secret 값은 Secret Manager에서 수동 조회 후 복사.

Phase 4 — 스택 시작 + Caddy 자동 HTTPS

gcloud compute ssh samba-wave-vm --zone=asia-northeast3-a \ --command='sudo systemctl start samba-stack \ && sudo docker compose -f /opt/samba/docker-compose.yml logs -f samba-api'

Caddy가 도메인 DNS A 레코드(VM 외부 IP)를 검증하고 Let's Encrypt 인증서를 자동 발급/갱신합니다. 사람이 손댈 일 없습니다.

운영 명령어

# 로그 sudo docker compose -f /opt/samba/docker-compose.yml logs -f samba-api # 재시작 (env 변경 후 등) sudo docker compose -f /opt/samba/docker-compose.yml restart samba-api # 수동 배포 (이미지 pull + 재기동) sudo docker compose -f /opt/samba/docker-compose.yml pull samba-api sudo docker compose -f /opt/samba/docker-compose.yml up -d samba-api # 자원/디스크 점검 sudo docker stats sudo docker system df sudo docker system prune -af # 미사용 이미지 정리

DB 마이그레이션 (배포 전 필수)

최우선 규칙: CI/CD는 DB를 건드리지 않습니다. 마이그레이션은 반드시 수동으로 실행해야 합니다. 백엔드 배포 전에 먼저 적용하세요.

마이그레이션 파일 생성 (모델 변경 시)

cd backend # 모델 변경 후 누락 검증 (최우선) .venv/Scripts/python.exe scripts/check_migrations.py # 자동 생성 alembic revision --autogenerate -m "컬럼 추가 설명" # 산출물 육안 검토 — op.drop_table / op.drop_index 라인이 있으면 # 의도된 것인지 100% 확인. 의도 외 DROP이면 alembic/env.py 모델 import # 누락을 먼저 의심할 것.

프로덕션 DB에 적용

# 1) Cloud SQL Auth Proxy 기동 cloud-sql-proxy fresh-sanctuary-489804-v4:asia-northeast3:samba-wave-db & # 2) 환경변수 후 alembic upgrade set WRITE_DB_HOST=127.0.0.1 set WRITE_DB_PORT=5432 set WRITE_DB_NAME=railway set WRITE_DB_USER=postgres set WRITE_DB_PASSWORD=<시크릿> alembic upgrade head alembic current # 적용 결과 확인
성공 확인: "Running upgrade ... -> head" 출력 + alembic_version 테이블의 head 일치.

프론트엔드 Vercel 배포

Vercel 프로젝트 최초 연결 (1회)

  • vercel.com → GitHub으로 로그인
  • Add New Project → samba-wave 리포 선택
  • Root Directory: frontend
  • Framework Preset: Next.js (자동 감지)
  • Environment Variables 추가 후 Deploy

Vercel 환경변수

# Vercel → 프로젝트 → Settings → Environment Variables NEXT_PUBLIC_API_URL = https://api.samba-wave.co.kr # VM 도메인 사용. legacy Cloud Run URL을 쓰던 시절은 한시적으로 병행 가능.
이후 git push origin main만 하면 Vercel이 감지해 자동 재배포합니다. 별도 작업 불필요. 프론트만 수정 시 GitHub Actions는 실행되지 않습니다(비용 절약).

헬스체크 / 운영

헬스체크 엔드포인트

# VM (신규) curl https://api.samba-wave.co.kr/api/v1/health curl https://api.samba-wave.co.kr/healthz # Cloud Run (legacy, 병행) curl https://samba-wave-api-XXXX-an.a.run.app/healthz

/healthz 응답에는 다음이 노출됩니다:

  • commit_sha — 현재 배포된 커밋 해시 (배포 검증용)
  • deployed_at — 배포 시각 (UTC)
  • cancel_paused — 작업취소 일시정지 상태 (true면 일괄 일시중지 중)

로그 확인

# VM gcloud compute ssh samba-wave-vm --zone=asia-northeast3-a sudo docker compose -f /opt/samba/docker-compose.yml logs -f samba-api # Cloud Run (legacy) gcloud run services logs read samba-wave-api \ --region=asia-northeast3 --limit=50 # GitHub Actions 워크플로우 GitHub → Actions → Deploy to GCE VM → 최신 run

배포 순서 · 트러블슈팅

표준 배포 순서

  1. ① DB 마이그레이션 — 로컬에서 Auth Proxy로 alembic upgrade head
  2. ② 백엔드 — Cloud Build 자동 (push) 또는 deploy-vm.yml 수동 트리거
  3. ③ /healthz 검증 — commit_sha가 현재 커밋과 일치하는지 확인
  4. ④ 프론트엔드 — Vercel은 push 시 자동 배포 (별도 액션 없음)

자주 발생하는 문제

증상원인해결
VM 배포 후 502 / 헬스체크 실패 이미지 pull 실패 또는 .env 누락 sudo docker compose ps + logs samba-api 확인. /opt/samba/.env 존재 여부 점검
DB 연결 실패 (cloud-sql-proxy) sa-key.json 권한 부족 또는 누락 서비스계정에 roles/cloudsql.client 부여. logs cloud-sql-proxy 확인
Caddy HTTPS 발급 실패 도메인 DNS A 레코드가 VM IP를 가리키지 않음 DNS 전파 확인 후 docker compose restart caddy
마이그레이션 컬럼 없음 오류 배포 전 마이그레이션 미실행 alembic upgrade head 후 백엔드 재배포
Cloud Build 실패 Dockerfile 오류 / 메모리 부족 Cloud Build 콘솔 → 빌드 로그 확인
CORS 에러 CORS_EXTRA_ORIGINS 미설정 VM /opt/samba/.env에 Vercel URL 추가 후 restart samba-api
Vercel 빌드 실패 TypeScript 타입 오류 / 환경변수 누락 Vercel → 해당 배포 → Build Logs 확인
VM 디스크 가득 참 이미지 누적 sudo docker system prune -af
재부팅 후 스택 미기동 최초 1회는 수동 시작 필요 sudo systemctl start samba-stack

롤백

VM: Artifact Registry의 이전 태그(SHA)로 image를 변경 후 docker compose up -d samba-api. :latest 대신 특정 SHA 태그로 명시적 롤백 권장.

Cloud Run: gcloud run services update-traffic samba-wave-api --to-revisions=<PREVIOUS>=100 --region=asia-northeast3

Vercel: Deployments 탭 → 이전 배포 ⋯ → Promote to Production (재빌드 없음)

DB: alembic downgrade -1 — 단, downgrade 함수 검증 필수. 데이터 손실 가능성 있음.
