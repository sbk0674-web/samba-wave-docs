Google Cloud 프로젝트 설정

1
GCP 프로젝트 생성
console.cloud.google.com → 프로젝트 선택 → 새 프로젝트. 프로젝트 ID를 기록해두세요.
2
필요한 API 활성화
터미널에서 실행:
# gcloud 초기화 (최초 1회)
gcloud auth login
gcloud config set project YOUR_PROJECT_ID

# API 활성화
gcloud services enable compute.googleapis.com
gcloud services enable sqladmin.googleapis.com
gcloud services enable artifactregistry.googleapis.com
3
Artifact Registry 저장소 생성
gcloud artifacts repositories create cloud-run-source-deploy \
  --repository-format=docker \
  --location=asia-northeast3 \
  --description="Samba Wave API"

# Docker 인증 설정 (최초 1회)
gcloud auth configure-docker asia-northeast3-docker.pkg.dev
4
서비스 계정 생성 (Cloud SQL 접근용)
# 서비스 계정 생성
gcloud iam service-accounts create samba-sql-proxy \
  --display-name="Samba SQL Proxy"

# Cloud SQL 권한 부여
gcloud projects add-iam-policy-binding YOUR_PROJECT_ID \
  --member="serviceAccount:samba-sql-proxy@YOUR_PROJECT_ID.iam.gserviceaccount.com" \
  --role="roles/cloudsql.client"

# 키 파일 생성 → VM에 올릴 sa-key.json
gcloud iam service-accounts keys create sa-key.json \
  --iam-account=samba-sql-proxy@YOUR_PROJECT_ID.iam.gserviceaccount.com
2

Cloud SQL 데이터베이스 생성

1
Cloud SQL 인스턴스 생성
GCP 콘솔 → SQL → 인스턴스 만들기 → PostgreSQL 선택
인스턴스 IDsamba-wave-db
리전asia-northeast3 (서울)
머신 타입db-f1-micro (최소)
PostgreSQL 버전PostgreSQL 14
비밀번호안전한 비밀번호 설정 후 메모
2
DB 사용자 및 데이터베이스 생성
인스턴스 생성 후 → 데이터베이스 탭 → 데이터베이스 만들기
📋 생성할 항목
• 데이터베이스 이름: samba-wave
• 사용자: samba-user (비밀번호 설정 필요)
• 연결 이름 메모: YOUR_PROJECT_ID:asia-northeast3:samba-wave-db
3
로컬에서 DB 마이그레이션 실행
Cloud SQL Proxy로 로컬에서 접속해 테이블 생성
# Cloud SQL Proxy 실행 (별도 터미널)
cloud-sql-proxy YOUR_PROJECT_ID:asia-northeast3:samba-wave-db

# .env에 localhost DB 설정 후 마이그레이션
cd backend
alembic upgrade head
3

GCE VM 인스턴스 생성 및 설정

1
VM 인스턴스 생성
GCP 콘솔 → Compute Engine → VM 인스턴스 → 만들기
머신 타입e2-medium (2vCPU, 4GB)
리전asia-northeast3-a (서울)
OSUbuntu 22.04 LTS
부팅 디스크30GB SSD
방화벽HTTP, HTTPS 트래픽 허용 체크
SSH 키본인 공개키 등록 (ssh-keygen으로 생성)
2
VM에 Docker 설치
VM SSH 접속 후 실행
# Docker 설치
curl -fsSL https://get.docker.com | sh
sudo usermod -aG docker $USER
newgrp docker

# 배포 디렉토리 생성
sudo mkdir -p /opt/samba
sudo chown $USER:$USER /opt/samba
3
/opt/samba/.env 파일 생성
VM SSH에서 환경변수 파일 작성
# /opt/samba/.env

ENVIRONMENT=production

# DB (cloud-sql-proxy가 같은 Docker 네트워크에서 포트 5432로 터널)
WRITE_DB_USER=samba-user
WRITE_DB_PASSWORD=(Cloud SQL에서 설정한 비밀번호)
WRITE_DB_HOST=cloud-sql-proxy
WRITE_DB_PORT=5432
WRITE_DB_NAME=samba-wave

READ_DB_USER=samba-user
READ_DB_PASSWORD=(위와 동일)
READ_DB_HOST=cloud-sql-proxy
READ_DB_PORT=5432
READ_DB_NAME=samba-wave

DB_SSL_REQUIRED=false
JWT_SECRET_KEY=(openssl rand -hex 32 로 생성한 값)
SAMBA_INVITE_CODE=(openssl rand -hex 12 로 생성 — 본인만 아는 회원가입 비번. 미설정 시 가입 전면 차단)
AWS_EC2_METADATA_DISABLED=true
4
sa-key.json 업로드
1단계에서 생성한 서비스 계정 키를 VM에 복사
# 로컬 터미널에서 실행
scp -i ~/.ssh/deploy_key sa-key.json \
  YOUR_VM_USER@YOUR_VM_IP:/opt/samba/sa-key.json
4

로컬 배포 스크립트 설정

1
deploy/deploy.sh 설정 수정
본인 프로젝트 ID와 VM 정보로 교체
# deploy/deploy.sh 상단 설정 섹션
PROJECT_ID="YOUR_PROJECT_ID"
AR_REGION="asia-northeast3"
AR_REPO="cloud-run-source-deploy"
IMAGE_NAME="samba-wave-api"
VM_HOST="api.yourdomain.com"  # VM IP 또는 도메인
VM_USER="YOUR_VM_USERNAME"
SSH_KEY="$HOME/samba-vm-secrets/ssh/deploy_key"

SSH 키를 지정 경로에 저장
mkdir -p ~/samba-vm-secrets/ssh
cp YOUR_PRIVATE_KEY ~/samba-vm-secrets/ssh/deploy_key
chmod 600 ~/samba-vm-secrets/ssh/deploy_key

deploy/vm/docker-compose.yml 수정
이미지 경로의 프로젝트 ID를 본인 것으로 교체

🔧 문제가 생겼을 때

Q. deploy.sh 실행 시 "permission denied"
→ SSH 키 권한 확인: chmod 600 ~/samba-vm-secrets/ssh/deploy_key
Q. Docker push 실패 (unauthorized)
→ AR 인증 재설정: gcloud auth configure-docker asia-northeast3-docker.pkg.dev
Q. 헬스체크 실패 (DB 연결 오류)
→ VM에서 sudo docker compose logs cloud-sql-proxy 로 프록시 상태 확인. sa-key.json 권한 및 경로 확인.
Q. HTTPS 접속 불가 (Caddy 오류)
→ 도메인 DNS가 VM 외부 IP를 가리키는지 확인. 방화벽에서 443 포트 허용 여부 확인.
Q. VM 컨테이너 상태 확인
→ sudo docker compose ps 및 sudo docker compose logs -f samba-api
Q. 마이그레이션 실패 — LockNotAvailableError (alembic_version 잠금)
→ idle in transaction 연결이 alembic_version 테이블 lock을 잡고 있는 것.
1. kill_idle.py: asyncpg.connect → pg_terminate_backend WHERE state='idle in transaction'
2. sudo docker cp kill_idle.py samba-samba-api-1:/tmp/kill_idle.py
3. sudo docker exec samba-samba-api-1 /app/backend/.venv/bin/python /tmp/kill_idle.py
4. remaining=0 될 때까지 반복 후 deploy.sh 재실행
⚠ docker stop 절대 금지
Q. 배포 후 503 / DB connection pool 고갈
→ pg_stat_activity 확인. pool_pre_ping=False 설정 확인 (asyncpg 버그 대응). write pool 최대 40개, read pool 최대 15개 한도 확인.
